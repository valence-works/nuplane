# Native installed-package resolution inputs

## Implemented increment

`PackageInstallStore` now provides live-borrow overloads for completion-marker probes and bounded canonical archive-hash reads. Each uses the operation's original native filesystem, no-follow handles, single-link regular-file checks, same-volume and exact-name/profile checks, and before/after identity replay. Path-only probes and hash reads classify positively Unenrolled paths before accessing payload metadata; enrolled or uncertain paths refuse. Missing files and canonical-invalid hash contents return false/null as appropriate. IO or permission failures no longer become an assumed missing hash: uncertainty propagates rather than being disguised as a cache miss.

A separate internal admitted-operation missing-suffix target allows a root-scoped Complete operation to observe an exact cache miss through its nearest held native parent. It replays the absent edge and Complete root/ledger evidence before and after the callback. The legacy unenrolled-only missing-suffix target still refuses observed authority. A path-restricted operation that admitted a concrete directory refuses its later disappearance instead of turning it into a cache miss.

`NativePackageGraphFileReader` copies the top-level deterministic first nuspec and sorted relative runtime-asset names through held native directories. It refuses links, unfamiliar entry kinds, multiple-link files, cross-volume entries, changed profiles or identities, and bounded enumeration/depth/nuspec overflows. Every traversed directory must retain native no-follow absence of the reserved authority marker: an outer borrow cannot authorize a nested store. The marker is never opened or parsed, and native lookup supplies each directory's own name equivalence rules. XML DTDs and external resolution are prohibited. The complete tree is replayed after reading so a same-name replacement or newly appearing authority in an earlier subtree cannot hide behind unchanged top-level basenames. Detached inputs are cached once per resolved package and used consistently for dependency expansion, NuGet selection and node projections; runtime assets are no longer enumerated repeatedly for each projection.

Initial migration fixtures now resolve their actual graphs before declaring enrollment incomplete. Tests building a newer state under Complete enrollment pass an appropriate existing borrow into the actual native reader. The path-restricted coordinated-state test prepares its detached candidate under a separate short root-wide operation before taking the restricted borrow; subsequent state reads and publications use that restricted borrow. It proves state operations through a path-restricted owner, not multi-path graph-read coverage. No borrow is widened to repair the test.

## Concurrent first-install correction

The full Runtime regression exposed a real race: another ordinary first installer can create an absent path component while native admission is confirming or replaying its absence. The unscoped package-directory probe now performs an entirely fresh classification only when repeated no-follow observations identify the same newly appeared ordinary directory and retain the same parent identity/name profile. The private retry cause is wrapped in the public `UnknownAuthority` refusal and emitted only after all existing path/authority evidence is replayed. There are at most two fresh classifications after the initial attempt; each failed attempt disposes its native handles. Ordinary resolver callers, enrolled paths, links/files, identity or profile drift, callback errors and post-callback changes remain strict refusals. The callback is never retried.

The complete automatic route still requires actual nonempty transition/protected-state publication: explicit guards in the diff/transaction middleware and owned registry are retained. This is separate from the exact-head evidence above and does not remove those transition guards.
