# Exact quarantine and recovery contract

This is the internal T106–T113/T118 protocol under the [manual-maintenance contract](maintenance.md). It adds no public operation or owner-policy choice. Records are detached evidence; parsing, a stored phase, a preview identity, or a matching digest never grants mutation authority. The real T105 two-composition/before-read gate is accepted; full driver and public activation gates remain required.

## Ownership and candidate binding

Execution holds a live exact catalog-owner operation and the complete root/all-state lock union. It verifies configured root identity/epoch, every member revision/digest, live uses and current inventory, then creates a fresh retention plan. Only an Eligible row can bind a deletion candidate. Retain native canonical root-to-parent ancestry, parent identity/name profile, original install directory identity, and exact completion-marker identity/digest. Internal call-scoped bindings derive from this live owner, never from a decoded journal. Revalidate retained evidence before mutation. No lexical path fallback, automatic pruning, automatic replay or quarantine moveback is allowed.

Use the existing same-parent native no-replace directory publisher to move the install to `.nuplane-quarantine-<candidate-id:N>` under its package-ID parent. Operation and candidate IDs are nonempty, separate GUIDs. Candidate IDs identify individual installs, even within one operation. The original three-component feed/package/version logical identity remains separate from the quarantine location. Destination absence, exact source identity/spelling, same volume and parent profile must be verified. Publication exceptions may follow a completed move; preserve evidence and inspect actual names instead of blindly retrying.

## Prepared journal and exact baseline

Before the first namespace mutation, capture the complete bounded install tree and persist/flush/round-trip/native-identity verify a Prepared journal containing the full baseline. Close descendant/marker/install read handles before the move on Windows, retaining the verified package-ID parent. All phases carry the same baseline; no separate sidecar or optional late baseline is used. Native control-file phase replacement binds the expected prior identity. Reconcile only exact known publication artifacts against their candidate/context; unknown, orphaned or ambiguous artifacts are preserved and refused. File flushes do not establish a power-loss guarantee or atomicity with the directory rename.

The journal binds schema version, root identity and positive enrollment epoch, operation/candidate IDs, original PackageInstallIdentity, exact two-component parent locator and parent identity/name profile, original basename, unique quarantine basename, completion-marker native identity, the confirmed nonnegative KeepNewestInactiveVersionsPerPackage value, phase, full native-entry manifest and an integrity digest over every field. Missing retention never produces a deletion journal. The original install root/path/directory/completion digest must agree with these bindings. Supported phases are Prepared, Quarantined, Deleting and Finalizing; a journal does not store an attributed Deleted claim.

The manifest names its root fields InstallDirectoryIdentity and InstallDirectorySemantics, binding the install directory identity and its name profile, then every descendant's exact install-relative component sequence, Directory or RegularFile kind, native identity, parent identity/name profile and (for directories) its own name profile. The root is not repeated as a descendant. Every non-root parent must occur as a Directory row; all child bindings must match that row. Every journal baseline must contain the exact root `.nuplane-ready` regular-file row matching the journal marker identity/completion digest. A detached manifest may also describe a current markerless or empty Finalizing subset; only phase-aware native validation can accept that observation, and subset comparison alone grants no authority. Native identities are unique across the tree (regular hard links refuse), all objects share the same provider/volume, and distinct native objects cannot share an identity. Repeated parent references must equal their actual parent row or manifest install root; they are not separate objects. The journal additionally requires the store root, package-ID parent and install directory to have distinct native identities. A component is one strict native-encoding component, at most 255 encoded bytes and 255 UTF-16 code units. No normalization or managed case folding establishes native equivalence.

Bounds: at most 16,384 descendant entries, 1,024 direct children per directory, 64 descendant components and 16 MiB encoded journal. Prune journal discovery uses at most 1,024 artifact names and 64 MiB aggregate encoded bytes across all recognized journals and staging artifacts. These are separate prune budgets; the existing shared control-directory enumeration cap 4,096 still applies before graph-use/prune filtering and supplies no independent prune headroom. Exceeding any bound refuses without truncation, move or unlink. Detached models and codecs enforce structural bounds; actual native capture/revalidation enforces canonical spelling, supported profiles, link/reparse refusal, single-link regular files and complete bounded enumeration. The digest is integrity evidence, not proof that the namespace is current. Models copy input collections and serialize entries in ordinal component order with deterministic field encoding. Unknown fields, duplicate JSON properties, missing fields, invalid enums, unsupported versions, invalid UTF and digest mismatches refuse.

Canonical journals reside at `.nuplane-store/prune-<candidate-id:N>.json`. Exact known publication stages bind the same candidate and a distinct nonempty publication ID. Every recognized stage counts toward the artifact and read budgets; unknown, malformed or orphan evidence is preserved/refused. No prefix-only cleanup is allowed. This flat prune prefix is distinct from graph-use's `use` namespace. Native publication/discovery integration must freeze exact stage naming/reconciliation and safe terminal-journal retention/retirement before activation, so indefinite accumulated journals cannot silently exhaust the namespace. The detached codec never creates or retires an artifact.

## Phase and resume rules

| Durable phase and actual native evidence | Required action |
| --- | --- |
| Prepared; exact original tree matches full baseline, quarantine absent | The current explicit Execute may continue its verified Prepared→move transition under retained ownership and current eligibility. A later invocation requires a new explicit Execute and fresh eligibility before moving. Keep only the current inventory candidate; do not add a duplicate journal candidate. |
| Prepared or Quarantined; exact quarantine tree matches full baseline, original absent | Rebind current parent/root/marker and replan the journal's original logical install before continuing. |
| Prepared or Quarantined; missing baseline entry, added/replaced entry, both names present, or neither name present | Refuse and preserve contradictory/ambiguous evidence. |
| Deleting; exact marker intact, remaining tree is an exact baseline subset | Report observed missing-entry/partial facts, then fresh eligibility may permit further walking. |
| Deleting; quarantine or marker absent | Refuse contradictory phase evidence; do not infer completion. |
| Finalizing; marker is the sole exact child | Fresh eligibility may permit exact marker removal followed by empty-root removal. |
| Finalizing; marker absent and exact quarantine root is empty | Report PartiallyRemoved; fresh eligibility may permit empty-root-only removal. |
| Finalizing; quarantine positively absent after restart | AlreadyAbsent; never attribute deletion to the previous process. |
| This invocation performs final exact native root removal and verifies absence | Deleted is supported by that invocation's receipt. |

After quarantine, verify the full baseline again before advancing. Persist/verify Deleting before the first payload unlink. During Deleting, preserve the exact root completion marker; remove files/empty directories only after current exact baseline identity/name/profile revalidation. Surviving names/identities must all be baseline members; added names, replaced survivors, links/reparse points, cross-volume entries and changed profiles refuse further walking. Missing baseline members establish physical partial facts without claiming which process removed them. Native empty-directory removal must refuse an unexpected appeared child.

Persist/verify Finalizing only after a complete bounded enumeration proves that the exact completion marker is the sole remaining child. Close marker/leaf handles before native removal; adapters reopen and validate the actual removal handle. In Finalizing accept only marker-only or positively empty root states; an extra child or marker mismatch refuses, with no fallback walker.

Every restart/resume requires a new explicit Execute request, current configured root/epoch/retention confirmation, complete current locks/protection and fresh planning. Join verified quarantines into a dedicated execution view using their journal-bound original logical identities beside current completed installs; the ordinary inventory's invalid-version IncompleteInstall classification alone is insufficient. A Prepared journal whose exact original remains present contributes no duplicate candidate. Unknown prefix-only entries remain excluded/refused. The native inventory/journal join must be tested before executor activation. A replacement at the original path must retain the planner's IdentityConflict refusal; never weaken it to finish cleanup. Newly protected, budget-retained or uncertain candidates stay quarantined/partial with current reasons. A markerless Finalizing directory is PartiallyRemoved, never a usable retained package. Cancellation and I/O faults preserve observed completed facts and uncertain evidence.
