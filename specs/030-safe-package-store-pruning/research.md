# Research: safe manual package-store pruning

**Decision date:** 2026-10-09. **Source baseline:** `eb2cf6c2ee1f79dc2c45fb83cc415bbe4856d0d4`; product files unchanged through planning head `03b48ac`. This records engineering selections under the existing delivery authorization. It is not implementation or package-deletion acceptance.

## Physical authority and native operations

**Decision:** core owns a narrow internal native filesystem adapter. Identify a root from its open directory handle, not its configured spelling. Probe authority by opening directory metadata, walking physical parents and opening only the reserved control record without following its final component. Return Enrolled, positively Unenrolled, or Unknown. Missing targets, unsupported operations, malformed/incomplete records and identity disagreement are Unknown. Ordinary package I/O on Unknown is denied. A normal access cannot enroll a root.

Traverse original path components using metadata-only held handles and record any authority encountered before following an alias. An alias transition from an enrolled ancestor to outside/different physical authority is Unknown, never Unenrolled. Validated configured-root aliases that converge to the same physical root remain supported. Refuse final install/member/content links; archive targets with hardlink ambiguity are Unknown. A resolved-target parent walk alone is insufficient. The probes below do not test this complete component-wise algorithm.

For Unix use directory descriptors, `openat`, no-follow metadata and same-device identity checks; quarantine by `renameat` and walk/delete relative to held descriptors with `unlinkat`. Darwin uses its independently verified native ABI; Linux uses `statx` with descriptor-relative/empty-path metadata and a checked returned mask, avoiding an assumed shared `struct stat` layout. Native entry-point absence or unsupported filesystem semantics refuses enrolled operations. Windows uses directory handles, volume/file identity, `NtCreateFile` with `RootDirectory` and reparse-point inspection, and handle-based rename/disposition. Enumerate relative to held directories; do not enumerate a textual path then recursively delete it. Validate ABI sizes/offsets, error conversion, filename encoding, reparse/link checks and identity preservation in platform tests before enabling destructive capability.

**Rationale:** paths and symlink resolution alone do not retain the object checked before a later filesystem action. Open handles make the identity being authorized explicit. The adapter is internal; no new package or native helper deployment is selected.

**Alternatives rejected:** lexical prefix checks followed by `Directory.Delete(..., recursive: true)`; DI-only authority lookup that public static readers bypass; using a per-state lock as root authority; requiring proof that no hostile same-UID nonparticipant exists. The support contract covers admitted cooperating clients and quiescent enrollment. Arbitrary nonparticipating file access is outside that contract. No user callback runs inside pruning's critical section.

Primary platform references: [Windows relative opens](https://learn.microsoft.com/en-us/windows/win32/api/winternl/nf-winternl-ntcreatefile), [Windows handle operations](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle), [Linux statx](https://man7.org/linux/man-pages/man2/statx.2.html). These describe mechanisms, not runtime qualification.

## Design-probe evidence and its limits

An artifact-only C probe ran on local Darwin arm64: source SHA-256 `eba880300e723baf2941a2748f6d2aa804e64c7ed910e9ea22d9293fb044241b`; final log `3b7677fdffd06e502d4f3e029924008706c53292d4449a695301d54be0668831`. Removing the final no-follow guard or marker/root identity comparison each failed its targeted assertion; restored source passed. Independent review accepted only that scope. The alias targets a descendant directory, not a second root-lock spelling.

A .NET 10 interop probe then built with zero warnings/errors and passed eight assertions: source `1645023a0d8e617c528ca2a3418e63297e4eb4c3dc05c0dd54ee1e7ca069c184`, log `77794d25b08bf3c397dd7857b959567e97ed1091410a61818cfc0640c167e0d0`. It established observed Darwin `stat` size144, device offset0, mode offset4, inode offset8 with managed safe handles; alias-descendant parent identity; held-root replacement; empty relative quarantine rename; no-follow failure; and changed state inode after `File.Replace`. Its no-follow assertion accepts any open failure, so it is mechanism evidence, not an errno-specific causal .NET test. Both independent reviews accepted the limited claims. Every owned fixture was removed and every probe process exited.

Neither probe used actual Nuplane components, graph leases, root locks, package deletion or recursive traversal. Neither supplies Windows/Linux acceptance or power-loss proof. Raw sources/logs/reviews are retained in the delivery workspace's `native-authority-probe/` and `native-authority-probe/dotnet/`; product tests must reproduce the mechanisms rather than depend on those local artifacts.

## Membership, state slots and publication

**Decision:** use a versioned root ledger with an enrollment epoch, Incomplete/Complete status, the complete declared member set and a single pending state transition. Each member binds a stable state slot: physical parent-directory identity plus validated basename/case policy. The current state-file identity is an observed revision/race token, not a permanent membership key. Atomic replacement changes file identity during legitimate writes. Reject final symlinks, hardlink ambiguity and changed parent/name binding; support validated parent aliases that converge to the same slot.

Enrollment and membership changes require the complete old/new member set and an explicit fully quiescent cutover. Publish Incomplete first; lock all states deterministically; validate and write every member's protection; publish Complete last. **Complete requires known complete active and recoverable LKG closures for every member; KnownEmpty is valid, absent metadata is not.** Unknown legacy LKG keeps authority Incomplete and ordinary package I/O denied. The draft alternative allowing active-only admission with unknown LKG is not selected.

For every enrolled state write, acquire root ownership before state ownership, publish pending prior/next revision and canonical state/protection digests, atomically replace the state including protection, verify its unchanged slot and exact next payload, then acknowledge its new file identity/revision and clear pending. All state writers participate, including failures/source snapshots; no writer may silently preserve a stale observed identity. On restart, exact prior or next evidence can recover under ownership; third/missing/ambiguous evidence remains refused. Recovery records are not discarded merely because a destination exists.

**Rationale:** one file replacement can atomically contain state and protection, but the ledger and member files are not one filesystem transaction. A pending transition makes an interrupted publication visible. The existing `AtomicFileWriter` supplies temp flush and handled-failure replacement/backup semantics, not cross-file atomicity or power-loss durability. Reuse its serialization/failure seams and preserve its safeguards; enrolled writes need the native adapter's held-directory/no-follow replacement operations. Test process termination at each publication boundary. Do not claim directory-fsync or power-loss guarantees without separate evidence.

**Alternatives rejected:** fixed state inode membership; treating missing legacy protection as empty; recording only the currently online state; replacing historical graph protection with the current graph.

## Exact graph and historical recovery protection

**Decision:** add a nullable non-positional protection property to `StoreStateRecord`, preserving its seven-position constructor/deconstruction and legacy normalizers. Deep-copy it in `StoreRegistry.GetStateAsync`; round-trip it through the serializer. Add an optional `IPackageProtectionStateSerializer : IStoreStateSerializer` participation companion. The default serializer implements it; unclassified custom serializers refuse before enrollment without changing the existing interface. Declared participation is not sufficient by itself: every publication reopens and validates the exact expected protection/state digest, and dropped metadata leaves authority incomplete. Capture complete resolved graph nodes and immutable install identities at the real successful state-transition seam. Persist independent recoverable graph snapshots and explicit retirement evidence.

`LastKnownGoodById` is a per-package ID/version map, not a complete historical dependency graph. Migration must either verify supplied full graph/path evidence or leave the legacy recovery promise Unknown. A normal success cannot erase an unknown promise. Explicit quiescent retirement is an operator migration action that updates recovery metadata together with protection, not an implicit cleanup policy. Retire a known historical graph only when the same durable transition makes it unselectable; uncertain mixed-version recovery protection remains conservative.

The whole install directory is protected, including dependency/support/native assets used lazily. Active/LKG/live protection is mandatory regardless of retention settings. Retained history may be compacted only after explicit retirement; it never becomes deletion authority itself.

## Short operation ownership and graph lifetime

**Decision:** use sealed opaque owner/borrow handles with non-public construction and exact-root/epoch/handle validation. Borrow creation and close linearize under a small local gate. Close rejects new borrows and waits for existing borrows before releasing the root lock. No gate is held while awaiting child work. Nested calls consume an explicit borrow; no `AsyncLocal` boolean or recursive root acquisition.

Transient resolver/acquisition/metadata I/O stays within short root ownership, which excludes pruning while the graph is still being discovered. It does not fabricate a complete graph lease before resolution is complete. Before any selected graph is handed to a retained reader, metadata advisor, loader or lazy resolver, publish a complete immutable graph-use record under that owner. A validated pending graph may receive a lease; it need not already be committed active state. A lease view is checked and temporarily pinned for each scoped read; closing its owner waits for such reads, so disposal cannot release protection during an authorized read.

Open an exclusive lifetime sentinel before publishing its immutable graph record, then publish before first retained read. Hold the sentinel for actual graph usage. A crash before record publication cannot have performed a retained read. Maintenance probes sentinels nonblocking under root ownership: busy plus valid record means protected, proven stale can be reaped, missing/mismatched/uncertain evidence refuses deletion. Never replace a held lock/sentinel inode. An orphan or failed stale cleanup is not silently ignored.

Loading transfers lease release ownership to an entry containing a weak context reference, not a strong Assembly/context/delegate. Context dictionary removal, `Unload`, `Unloading` and catalog replacement do not release protection. A core passive local weak-reference observer is scheduled only while collectible associations exist, with owned cancellation/drain and a fixed internal observation cadence. It checks weak death and closes lifetime sentinel ownership independently of later admissions, so an idle process does not indefinitely pin a dead context against a sibling pruner. It invokes no user callback, GC, unload or file deletion and is not an automatic pruning driver. Subsequent admissions may also sweep. Core observes weak object references without referencing Loading. Noncollectible contexts retain protection until process exit. Partial-load failures retain leases whenever a created context/resolver may still use files. The idle-owner child-process acceptance test must establish release without initiating another owner admission.

## Drivers, compatibility and public static readers

**Decision:** add optional scoped companions; preserve existing required resolver, observer, dispatcher, metadata, store and admin interfaces. Enrolled compositions require either a scoped path-using participant or an explicit path-independent participant contract where meaningful. Unsupported custom participants fail before package I/O. Unenrolled behavior stays compatible.

Carry the owner explicitly through reconciliation context, resolver/acquirer/install operations, gates/contributors, state publication and awaited observer dispatch. Loading receives that borrow, avoiding self-contention in a callback already under root ownership. Each standalone restore/catalog/scanner/metadata/loading driver must enter admission independently. See [contracts/admission.md](contracts/admission.md) for the complete driver obligations.

Legacy static `PackageContent.Try*` probes only physical authority first and returns null for Enrolled/Unknown. Add scoped overloads with typed refusal and an internal admitted parse/read core. Keep the metadata result's four-position constructor; add a refusal discriminator. Pure `NuplaneStore.ReadState`/active descriptor projection stays observational; returned paths are not leases. Scoped active snapshots discover roots from state metadata, acquire all roots in deterministic order, reread/validate the state and protect graphs before loading. Legacy host-integrated overloads refuse an entire Enrolled/Unknown request before any partial load.

## Manual API and retention

**Decision:** add a separate optional Admin maintenance interface; core admission never depends on Admin or a local prune flag. Provide inspect, default preview, explicit enrollment/recovery and explicit execute. Requests name configured root labels and retention, never caller-supplied deletion paths. Absent retention keeps all. The initial useful policy keeps a nonnegative number of newest unprotected versions per package; sort by NuGet version with deterministic identity ties.

Execution confirms the root's enrollment epoch and the retention request, then freshly reads all member states, live uses and inventory under root/all-state ownership. Protection changes since preview trigger a new plan, not reuse of preview candidates. Epoch/configuration changes refuse the old confirmation. Preview IDs correlate reports only; they are not authority or a required in-memory token cache. Validate each completed immutable install identity, quarantine relative to the held root, revalidate and delete through the native no-follow walker. Staging/unknown installs are excluded. Report retained, refused, quarantined/partially removed, deleted, already absent, failed and cancelled facts accurately.

**Alternatives rejected:** automatic pruning timer; treating existing policy-only `Deleted` actions as physical deletion; custom admin interface breaks; a stale preview authorizing old candidates; a process-local plan cache required for cross-process tooling.

## Remaining implementation acceptance

Design mechanisms are selected; runtime validation remains pending. Before physical deletion, pass real two-composition/different-state before-read admission proof. Then pass actual owned package deletion, offline historical LKG, lazy managed/native use, context lifetime, cross-process crashes, stale-preview, replacement/link/reparse, partial IO/cancellation and repeat execution on supported macOS/Linux/Windows. Preserve causal negative controls. A failed platform mechanism must be repaired before that platform's acceptance; it is not permission to narrow the feature.
